Methodology

How a game earns a green badge

1. Isolated bottles

Each attempt uses a separated Whisky, CrossOver, or native path so registry edits, DLL overrides, and renderers do not pollute other tests.

2. Visual proof

Playable means more than a process staying alive: the test needs a visible state, input-driven transition, and a repeatable recipe.

3. Public trail

Recipes live in linked GitHub repos. Sanitized evidence for this site is in data/evidence.json and the live source of truth is games.json.

4. Voting

Wishlist votes are GitHub issue thumbs-up reactions. The site reads anonymous REST API counts and sends voters to GitHub for the actual reaction.

Built from a Codex 5.5 + Claude retro-RTS testing session. No game files, keys, or private vault paths are shipped.
